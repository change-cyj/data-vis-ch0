6.1

盒模型Box Model

每个 HTML 元素都是一个矩形盒子——从 W3C 规范到 IE 怪异模式，理解 content / padding / border / margin 四层结构及其在布局中的连锁效应。Every HTML element is a rectangular box — from W3C specs to IE quirks mode, understanding the four-layer structure of content / padding / border / margin and their cascading effects in layout.

讲解Explanation

CSS 视觉格式化模型规定：每个元素生成一个或多个矩形盒子，由内到外依次为 content（内容区）→ padding（内边距）→ border（边框）→ margin（外边距）。padding 和 border 是"内层"——背景会覆盖到 border 外缘；margin 是"外层"——始终透明，不影响元素自身背景。The CSS visual formatting model specifies that each element generates one or more rectangular boxes, from inside out: content → padding → border → margin. Padding and border are "inner layers" — background extends to the border's outer edge; margin is the "outer layer" — always transparent, doesn't affect the element's own background.

W3C 标准盒模型（content-box）：width 仅设置 content 区域。设 padding 和 border 后，元素实际渲染宽度 = width + padding×2 + border×2。这在嵌套布局中极易导致溢出。W3C standard box model (content-box): width only sets the content area. After adding padding and border, the actual rendered width = width + padding×2 + border×2, easily causing overflow in nested layouts.

IE 怪异盒模型（border-box）：width 包含 content + padding + border。2008 年 IE8 引入 box-sizing 属性。Paul Irish 2014 年提出的全局 border-box 重置成为业界标配。IE quirks box model (border-box): width includes content + padding + border. IE8 introduced box-sizing in 2008. Paul Irish's 2014 global border-box reset became the industry standard.

margin 合并三规则：① 相邻兄弟元素的上下 margin 取较大值（非相加）；② 父元素无 padding/border 时，子元素的 margin-top 会穿透父元素；③ 空元素自身的 margin-top 和 margin-bottom 合并。合并只在 BFC 内发生。Margin collapse three rules: ① Adjacent siblings' vertical margins take the larger value (not summed); ② Without padding/border on parent, child's margin-top penetrates outside; ③ Empty element's own margin-top and bottom merge. Collapses only happen within BFC.

BFC（块级格式化上下文）是独立渲染区域。创建方式：display: flow-root（推荐）、overflow: hidden、display: flex/grid。BFC 阻止 margin 合并、阻止浮动塌陷。BFC (Block Formatting Context) is an isolated rendering area. Created by: display: flow-root (recommended), overflow: hidden, display: flex/grid. BFC prevents margin collapse and float collapse.

关键代码Key Code
/* Global box-sizing reset (Paul Irish, 2014) */
html { box-sizing: border-box; }
*, *::before, *::after {
  box-sizing: inherit;
}

/* Box model size calculation (border-box) */
.card {
  width: 320px;        /* incl. padding+border */
  padding: 24px;
  border: 2px solid #d4a04c;
  margin: 16px;      /* not in width */
}

/* Prevent margin collapse — create BFC */
.parent {
  display: flow-root;
}

6.2

定位机制Positioning

static / relative / absolute / fixed / sticky 五种定位值，决定元素如何脱离或在文档流中排列——以及由此衍生的包含块、层叠上下文与 z-index 管理问题。Five position values — static / relative / absolute / fixed / sticky — determine how elements flow or break from the document flow, along with containing blocks, stacking contexts, and z-index management.

讲解Explanation

定位的核心是"相对于谁"。static 按文档流排列；relative 相对自身原位置偏移，原位置保留；absolute 相对最近的非 static 祖先定位，脱离文档流；fixed 相对浏览器视口定位；sticky 是 relative + fixed 的条件混合体。Positioning is about "relative to what". Static: normal flow. Relative: offsets from original position, space preserved. Absolute: relative to nearest non-static ancestor, out of flow. Fixed: relative to viewport. Sticky: conditional mix of relative + fixed.

包含块（Containing Block）是定位参照系。absolute 的包含块是最近 position 非 static 祖先的 padding-box；fixed 通常相对视口。但关键规范变更：祖先有 transform/filter 时，fixed 的包含块变为该祖先——这导致 fixed 不再"固定"。Containing Block is the positioning reference. Absolute's containing block is the nearest non-static ancestor's padding-box; fixed is typically the viewport. But a key spec change: if an ancestor has transform/filter, fixed's containing block becomes that ancestor — breaking "fixed" behavior.

层叠上下文（Stacking Context）是 z-index 生效的前提。创建条件：position 非 static + z-index 非 auto、opacity < 1、transform 非 none 等。子元素的 z-index 不会穿透到外部上下文——这是模态框被遮挡的根因。Stacking Context is prerequisite for z-index. Created by: non-static position + z-index, opacity < 1, transform, etc. Child z-index cannot penetrate outside its context — the root cause of modals being obscured.

z-index 管理策略：推荐用 CSS 变量分层命名：--z-base: 1、--z-modal: 200、--z-toast: 300，避免魔法数字。z-index management: Use CSS custom property layers: --z-base: 1, --z-modal: 200, --z-toast: 300, avoiding magic numbers.

关键代码Key Code
/* Five position values */
.flow     { position: static; }
.shift    { position: relative; top: -8px; }
.badge    { position: absolute; top: 0; right: 0; }
.navbar   { position: fixed; top: 0; }
.toc      { position: sticky; top: 20px; }

/* z-index layer system via CSS vars */
:root {
  --z-dropdown: 100;
  --z-modal: 200;
  --z-toast: 300;
}
.modal { z-index: var(--z-modal); }

/* transform changes fixed's containing block! */
.parent { transform: translateZ(0); }

6.3

Flex 弹性布局Flexbox

一维布局的终极方案。Flexbox 以主轴/交叉轴双轴模型取代了 float+clearfix 时代，理解 flex 简写分解与 min-width:auto 陷阱是关键。The ultimate one-dimensional layout solution. Flexbox replaces the float+clearfix era with a main/cross-axis model. Understanding flex shorthand and the min-width:auto trap is key.

讲解Explanation

2009 年 Flexbox 首次提案，经历三个语法版本后于 2016 年定版。Flex 布局以主轴/交叉轴双轴模型为核心：flex-direction 决定主轴方向，justify-content 管主轴对齐，align-items 管交叉轴对齐。Flexbox was proposed in 2009, went through three syntax versions, and finalized in 2016. Its core is the main/cross-axis model: flex-direction sets main axis, justify-content controls main-axis alignment, align-items controls cross-axis alignment.

flex 简写：flex: 1 0 200px = flex-grow（剩余空间分配比例）、flex-shrink（收缩比例）、flex-basis（初始大小，优先于 width）。flex: 1 = 1 1 0%，flex: none = 0 0 auto。flex shorthand: flex: 1 0 200px = flex-grow (remaining space ratio), flex-shrink (shrink ratio), flex-basis (initial size, overrides width). flex: 1 = 1 1 0%, flex: none = 0 0 auto.

min-width: auto 陷阱：Flex 子项默认不允许收缩到内容最小宽度以下。内容过大时 flex-shrink 无效——元素溢出。修复：min-width: 0。这是最频繁的 Flex 溢出 bug。min-width: auto trap: Flex items default to not shrinking below content's minimum width. When content is too large, flex-shrink is ineffective — overflow occurs. Fix: min-width: 0. This is the most common Flex overflow bug.

gap（2021 年全浏览器支持）统一了 Flex 和 Grid 的间距语法，取代 margin + :last-child hack。align-self 覆盖单项对齐方式。gap (full browser support 2021) unifies Flex and Grid spacing, replacing margin + :last-child hacks. align-self overrides alignment for individual items.

关键代码Key Code
/* Flex container — dual-axis control */
.toolbar {
  display: flex;
  flex-direction: row;
  justify-content: space-between;
  align-items: center;
  gap: 12px;
}

/* flex shorthand = grow shrink basis */
.sidebar { flex: 0 0 240px; }  /* fixed */
.main    { flex: 1 1 0; }      /* adaptive */

/* Fix min-width:auto overflow trap */
.flex-child {
  min-width: 0;
  overflow: hidden;
}

/* Nav bar with flex:1 spacer */
.nav .spacer { flex: 1; }

6.4

Grid 网格布局CSS Grid

二维布局的终极方案。CSS Grid 在行列两个维度同时控制，配合 repeat() / minmax() / auto-fit 函数和 grid-template-areas，实现声明式布局。The ultimate two-dimensional layout solution. CSS Grid controls rows and columns simultaneously, with repeat() / minmax() / auto-fit and grid-template-areas for declarative layouts.

讲解Explanation

CSS Grid 于 2017 年全面落地。与 Flexbox 的一维不同，Grid 是二维布局——同时控制行和列。Grid 适合页面级布局，Flex 适合组件级布局。CSS Grid landed in all browsers in 2017. Unlike Flexbox's one-dimensional nature, Grid is two-dimensional — controlling rows and columns simultaneously. Grid for page-level layouts, Flex for component-level layouts.

fr 单位是"剩余空间的一份"。计算：先扣除固定轨道（如 200px），剩余空间按 fr 比例分配。例如 200px 2fr 1fr，容器 1000px：扣 200px，剩 800px 按 2:1 分。fr unit is "one share of remaining space". Calculation: deduct fixed tracks first (e.g., 200px), then distribute remaining space proportionally. E.g., 200px 2fr 1fr in 1000px container: 200px + 533px + 267px.

repeat(auto-fit, minmax(200px, 1fr)) 是黄金组合：auto-fit 让浏览器自动决定列数，minmax 约束每列范围——无需媒体查询即可响应容器宽度变化。这是 Grid 独有的能力。repeat(auto-fit, minmax(200px, 1fr)) is the golden combo: auto-fit lets the browser auto-determine column count, minmax constrains each column's range — no media queries needed for responsive layout. Grid-exclusive capability.

grid-template-areas 用字符串"画"出布局，配合 grid-area 命名，修改布局只需调整字符串顺序，HTML 不动。grid-template-areas uses strings to "draw" the layout. With grid-area names, changing layout only requires reordering strings — no HTML changes.

关键代码Key Code
/* Named areas — draw your layout */
.app {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar main  "
    "footer footer";
  grid-template-columns: 220px 1fr;
  gap: 12px;
}
.app > header { grid-area: header; }
.app > nav    { grid-area: sidebar; }

/* No-media-query responsive: auto-fit */
.gallery {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(200px, 1fr));
}

/* Named grid lines */
.layout {
  grid-template-columns:
    [nav-start] 200px [nav-end main-start]
    1fr [main-end];
}

6.5

响应式设计Responsive Design

从媒体查询到容器查询，从移动优先到内在设计——响应式不只是 @media，而是一整套适配多端的设计哲学。From media queries to container queries, from mobile-first to intrinsic design — responsive is not just @media, but a complete multi-device design philosophy.

讲解Explanation

2010 年 Ethan Marcotte 提出响应式设计三要素：弹性网格 + 弹性图片 + 媒体查询。核心是一份 HTML，多套 CSS，根据视口宽度动态切换布局。In 2010, Ethan Marcotte proposed responsive design's three pillars: fluid grid + flexible images + media queries. Core idea: one HTML, multiple CSS, dynamically switching layout based on viewport width.

移动优先（Luke Wroblewski）：先写小屏默认样式，用 @media (min-width: ...) 逐步增强大屏。断点应基于内容变形点而非设备尺寸。Mobile-first (Luke Wroblewski): Write small-screen defaults first, enhance with @media (min-width: ...). Breakpoints should be based on content deformation points, not device sizes.

clamp() 流体排版：clamp(1rem, 4vw, 3rem) = 最小值、理想值、最大值。无需媒体查询，字号随视口连续变化。clamp() fluid typography: clamp(1rem, 4vw, 3rem) = min, ideal, max. No media queries needed — font-size changes continuously with viewport.

dvh/svh/lvh（2022 年新增）：解决移动端 100vh 的地址栏收缩问题。推荐用 100dvh 替代 100vh。dvh/svh/lvh (2022): Solves mobile 100vh address-bar shrinkage. Use 100dvh instead of 100vh.

容器查询 @container（2023 年全浏览器支持）：让组件根据自身容器宽度而非视口响应——范式转变。同一组件在侧栏和主区可呈现不同布局。Container queries @container (full support 2023): Components respond to their own container width instead of viewport — a paradigm shift. The same component can render differently in sidebar vs. main area.

关键代码Key Code
/* Mobile-first: small default, enhance up */
.grid { grid-template-columns: 1fr; }
@media (min-width: 640px) {
  .grid { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 1024px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}

/* Fluid typography — clamp(min, ideal, max) */
h1 { font-size: clamp(1.5rem, 4vw, 3rem); }

/* Dynamic viewport height (2022) */
.fullscreen { height: 100dvh; }

/* Container queries (2023) */
.card-wrapper { container-type: inline-size; }
@container (min-width: 400px) {
  .card { display: flex; flex-direction: row; }
}
