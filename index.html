6.1

盒模型

每个 HTML 元素都是一个矩形盒子——从 W3C 规范到 IE 怪异模式，理解 content / padding / border / margin 四层结构及其在布局中的连锁效应。

讲解

CSS 视觉格式化模型规定：每个元素生成一个或多个矩形盒子，由内到外依次为 content（内容区）→ padding（内边距）→ border（边框）→ margin（外边距）。padding 和 border 是"内层"——背景会覆盖到 border 外缘；margin 是"外层"——始终透明，不影响元素自身背景。

W3C 标准盒模型（content-box）：width 仅设置 content 区域。设 padding 和 border 后，元素实际渲染宽度 = width + padding×2 + border×2。这在嵌套布局中极易导致溢出——例如父元素 width:300px，子元素 width:100% + padding:20px，实际渲染宽度为 340px，直接撑破父容器。

IE 怪异盒模型（border-box）：width 包含 content + padding + border。这意味着无论 padding 和 border 如何变化，元素的外围尺寸恒定不变。2008 年 IE8 率先引入 box-sizing 属性，允许开发者显式选择盒模型。2014 年 Paul Irish 提出的全局 border-box 重置成为业界标配：*, *::before, *::after { box-sizing: border-box }——注意 ::before 和 ::after 伪元素默认不继承 box-sizing，必须显式声明。

margin 合并三规则：① 相邻兄弟——两个块级元素的上下 margin 取较大值（非相加）；② 父子穿透——父元素无 padding-top/border-top/inline-block/flow-root 时，子元素的 margin-top 会"穿透"到父元素外部；③ 空元素自合并——空块级元素自身的 margin-top 和 margin-bottom 合并为较大值。合并只在块级格式化上下文（BFC）内发生。

BFC（Block Formatting Context）是一个独立的渲染区域，内部元素不受外部影响。创建 BFC 的方式：display: flow-root（语义最清晰，2017 年后推荐）、overflow: hidden/auto/scroll、display: flex/inline-block/grid、float 非 none。BFC 的三大效果：阻止 margin 合并、阻止浮动塌陷、阻止文字环绕浮动元素。

负 margin是合法的 CSS 技巧：负的 margin-right 可以让元素宽度"撑出"父容器；负的 margin-top 可以让后元素与前元素重叠。但负 margin 不改变元素尺寸，只改变与其他元素的间距计算。

关键代码
/* ── 全局盒模型重置（Paul Irish 2014）── */
html { box-sizing: border-box; }
*, *::before, *::after {
  box-sizing: inherit;  /* 继承 html 的 border-box */
}

/* ── 盒模型尺寸计算（border-box 模式）── */
.card {
  width: 320px;              /* 含 padding+border */
  padding: 24px;
  border: 2px solid #d4a04c;
  margin: 16px;          /* margin 不计入 width */
  /* content 实际宽度 = 320-24×2-2×2 = 268px */
}

/* ── 消除 margin 合并——创建 BFC ── */
.parent {
  display: flow-root;     /* 首选: 无副作用 */
  /* 备选: overflow:hidden / display:flex / float:left */
}

/* ── 负 margin 实战：撑满容器 + 重叠效果 ── */
.full-bleed {
  margin-left: calc(-50vw + 50%); /* 全宽 banner */
  margin-right: calc(-50vw + 50%);
}

6.2

定位机制

static / relative / absolute / fixed / sticky 五种定位值，决定元素如何脱离或在文档流中排列——以及由此衍生的包含块、层叠上下文与 z-index 管理问题。

讲解

定位的核心是"相对于谁"。static（默认）按文档流排列，top/left/right/bottom/z-index 全部无效；relative 相对自身原位置偏移，原位置仍保留（周围元素不会移动）；absolute 相对最近的非 static 祖先定位，脱离文档流（周围元素填补其位置）；fixed 相对浏览器视口定位，页面滚动时位置不变。

sticky 是条件混合体：在滚动未到达阈值前表现为 relative（占位保留），到达 top: 20px 阈值后切换为 fixed 行为（钉住位置）。但 sticky 有一个常被忽略的限制：sticky 元素的最近滚动祖先必须比 sticky 元素更高，否则 sticky 效果不会触发——如果父容器 overflow: hidden 且高度不足以滚动，sticky 等同于 static。

包含块（Containing Block）是定位的参照系，不同定位值的包含块不同：absolute 的包含块是最近的 position 非 static 祖先的 padding-box（注意不是 content-box）；fixed 的包含块通常是视口。但有一个关键的规范变更（CSS Transforms spec）：如果祖先元素有 transform、perspective、filter、will-change 等属性，fixed 的包含块会变成该祖先而非视口——这会导致 fixed 元素不再"固定"，是 2015 年后最常见的定位"坑"。

层叠上下文（Stacking Context）是 z-index 生效的前提。CSS 2.1 定义了 7 层堆叠顺序；CSS3 扩展了创建条件：position 非 static + z-index 非 auto、opacity < 1、transform 非 none、filter 非 none、isolation: isolate、mix-blend-mode 非 normal 等。层叠上下文的隔离性意味着：子元素的 z-index 无论多大，都不会穿透到外部上下文之上。这就是模态框（z-index: 9999）被父容器（有 transform）遮挡的根因。

z-index 管理策略：不要用 z-index: 99999 这种魔法数字。推荐用分层命名法：定义 CSS 自定义变量 --z-base: 1、--z-dropdown: 100、--z-modal: 200、--z-toast: 300，每个层级间隔 100 留扩展空间。这样团队协作时 z-index 层级清晰可控。

关键代码
/* ── 五种定位值——行为对比 ── */
.flow     { position: static; }          /* 文档流,top 无效 */
.shift    { position: relative; top: -8px; }  /* 偏移,原位保留 */
.badge    { position: absolute; top: 0; right: 0; }
.navbar   { position: fixed; top: 0; width: 100%; }
.toc      { position: sticky; top: 20px; }

/* ── z-index 分层管理——CSS 变量体系 ── */
:root {
  --z-base: 1;
  --z-dropdown: 100;
  --z-sticky: 150;
  --z-modal: 200;
  --z-modal-overlay: 210;
  --z-toast: 300;
}
.dropdown  { position: absolute; z-index: var(--z-dropdown); }
.modal     { position: fixed; z-index: var(--z-modal); }
.toast     { position: fixed; z-index: var(--z-toast); }

/* ── transform 改变 fixed 包含块（坑！）── */
.has-transform {
  transform: translateZ(0);
  /* 子元素的 fixed 不再相对视口, */
  /* 而是相对此元素定位! */
}

6.3

Flex 弹性布局

一维布局的终极方案。Flexbox 以主轴/交叉轴双轴模型取代了 float+clearfix 时代，理解 flex 简写分解与 min-width:auto 陷阱是掌握弹性布局的关键。

讲解

2009 年 Flexbox 首次提案，经历了三个语法版本：2009 语法（display: box，旧 WebKit/Firefox）、2011 语法（display: flexbox，微软草案）、2016 最终版（display: flex，W3C CR）。现代浏览器统一支持最终版。Flex 布局以主轴/交叉轴双轴模型为核心：flex-direction 决定主轴方向（row → 水平为主轴，column → 垂直为主轴），justify-content 管主轴对齐，align-items 管交叉轴对齐。

flex 简写分解：flex: 1 0 200px 三个值依次是——flex-grow（剩余空间分配比例，0 = 不伸不长）、flex-shrink（空间不足时的收缩比例，1 = 等比收缩）、flex-basis（初始大小基准，优先于 width 属性）。常用简写：flex: 1 = 1 1 0%（等比伸缩填充）、flex: auto = 1 1 auto（以内容大小为基准伸缩）、flex: none = 0 0 auto（固定不伸缩）。

flex-grow 的分配数学：容器剩余空间 = 容器宽度 - 所有子项 flex-basis 之和。每个子项分到的额外空间 = 剩余空间 × (自身 flex-grow / 所有子项 flex-grow 之和)。例如三个子项 grow 分别为 1、2、1，剩余空间 200px，分配为 50px、100px、50px。

min-width: auto 陷阱：Flex 子项默认 min-width: auto，意味着"不允许收缩到内容最小宽度以下"。当子项内容（如长 URL、长表格）超出容器时，flex-shrink 无法生效——元素溢出容器。解决方法：min-width: 0 或 overflow: hidden。这是 Flex 布局中最频繁出现的溢出 bug，几乎每个 Flex 项目都会遇到。

gap 属性（2021 年全浏览器支持）：统一了 Flex 和 Grid 的间距语法，取代了 margin + :last-child 的 hack 方案。在此之前，Flex 只能用 margin-right + .item:last-child { margin-right: 0 } 实现间距。

align-self 覆盖父容器 align-items 对单个子项的对齐方式，常用于让某个按钮在行内单独居顶或居底。flex-wrap 控制是否换行，换行后 align-content 控制多行间的间距——注意它只在 flex-wrap: wrap 时才有意义，单行布局下无效。

关键代码
/* ── Flex 容器：主轴/交叉轴双轴控制 ── */
.toolbar {
  display: flex;
  flex-direction: row;
  justify-content: space-between;  /* 主轴 */
  align-items: center;           /* 交叉轴 */
  gap: 12px;
}

/* ── flex 简写 = grow shrink basis ── */
.sidebar { flex: 0 0 240px; }   /* 固定 240px,不伸缩 */
.main    { flex: 1 1 0; }       /* 自适应填充剩余空间 */
.badge   { flex: none; }         /* 以内容为准,不伸缩 */

/* ── 修复 min-width:auto 溢出陷阱 ── */
.flex-child {
  min-width: 0;     /* 解除内容最小宽度限制 */
  overflow: hidden;  /* 或 text-overflow:ellipsis */
}

/* ── 导航栏布局实战 ── */
.nav {
  display: flex;
  align-items: center;
  gap: 16px;
}
.nav .spacer { flex: 1; }  /* 弹簧:推开左右两端 */
.nav .logo  { align-self: flex-start; }

6.4

Grid 网格布局

二维布局的终极方案。CSS Grid 在行列两个维度同时控制，配合 repeat() / minmax() / auto-fit 函数和 grid-template-areas 命名区域，实现声明式布局。

讲解

CSS Grid 于 2017 年 3 月在 Firefox 52、Chrome 57、Safari 10.1 全面落地，是 CSS 布局史上最重要的里程碑。与 Flexbox 的一维（一次只控制一个方向）不同，Grid 是二维布局——同时控制行和列。这意味着 Grid 特别适合页面级布局（header/sidebar/main/footer 整体结构），而 Flex 适合组件级布局（按钮组、表单行、卡片内部）。

fr 单位计算原理：fr 是"分数"单位，表示剩余空间的一份。计算顺序：先扣除固定轨道（如 200px、auto），剩余空间按 fr 比例分配。例如 grid-template-columns: 200px 2fr 1fr，容器宽 1000px：先扣除 200px，剩余 800px 按 2:1 分配——第二列 533px、第三列 267px。

显式网格 vs 隐式网格：grid-template-columns/rows 定义的是显式网格轨道。当子项数量超出显式网格范围时，Grid 自动创建隐式网格轨道，其大小由 grid-auto-rows/grid-auto-columns 控制，方向由 grid-auto-flow 决定（row：逐行填充，column：逐列填充，dense：回填空位）。

repeat() + minmax() + auto-fit 是自适应布局的黄金组合：repeat(auto-fit, minmax(200px, 1fr)) 的含义——auto-fit 让浏览器根据容器宽度自动决定列数（容器够宽就多列，不够宽就少列），minmax(200px, 1fr) 约束每列最小 200px、最大等分剩余空间。这完全不需要媒体查询即可实现从手机到桌面的响应式——这是 Grid 独有的能力，Flex 做不到。

grid-template-areas 允许用字符串"画"出布局结构。语法要求：每行用引号包裹、行列数必须一致、空位用 . 表示。配合 grid-area 命名，修改布局只需调整字符串顺序——HTML 结构完全不动。例如从"侧栏在左"改为"侧栏在右"，只需交换 areas 字符串中的两个词。

命名网格线是 areas 的进阶用法：grid-template-columns: [sidebar-start] 200px [sidebar-end main-start] 1fr [main-end]，然后 grid-column: sidebar-start / sidebar-end。这种方式在复杂布局中比 areas 更灵活。

subgrid（2023 年 Chrome 117 支持）允许子网格继承父网格的轨道定义，解决嵌套 Grid 对齐难题。此前嵌套 Grid 的行列轨道独立计算，无法与父网格对齐。

关键代码
/* ── 命名区域：像画图一样布局 ── */
.app {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar main  "
    "footer footer";
  grid-template-columns: 220px 1fr;
  grid-template-rows: auto 1fr auto;
  gap: 12px;
}
.app > header  { grid-area: header; }
.app > nav     { grid-area: sidebar; }
.app > main    { grid-area: main; }
.app > footer  { grid-area: footer; }

/* ── 无媒体查询自适应：auto-fit 魔法 ── */
.gallery {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(200px, 1fr));
  /* 容器>400px: 2列; >600px: 3列; ... */
  /* 容器<200px: 1列——自动响应! */
  gap: 16px;
}

/* ── 命名网格线——精确控制 ── */
.layout {
  grid-template-columns:
    [nav-start] 200px [nav-end main-start]
    1fr [main-end];
}
.layout > nav  { grid-column: nav-start / nav-end; }
.layout > main { grid-column: main-start / main-end; }

6.5

响应式设计

从媒体查询到容器查询，从移动优先到内在设计——响应式不只是 @media，而是一整套适配多端的设计哲学。

讲解

2010 年 Ethan Marcotte 在 A List Apart 发表《Responsive Web Design》一文，提出响应式设计三要素：弹性网格 + 弹性图片 + 媒体查询。核心思想是一份 HTML，多套 CSS——不根据 User Agent 判断设备，而是根据视口宽度动态切换布局。

移动优先（Mobile First）策略由 Luke Wroblewski 在 2009 年提出：先写小屏幕样式作为默认（通常最简、最核心），再用 @media (min-width: ...) 逐步增强大屏体验。这与渐进增强理念一致——小屏保底基础功能，大屏逐步提升体验。反过来用 max-width 则是"桌面优先"——在大屏基础上做减法，容易遗漏小屏核心功能。

断点选择不应基于设备尺寸（iPhone 是 375px、iPad 是 768px——设备每年在变），而应基于内容流动的变形点：在某个宽度下，如果内容开始拥挤（列宽太窄、文字换行混乱）或留白过多（图片太小、行宽过长），就该加断点。常见的实践方法：打开浏览器 DevTools 拖拽视口宽度，找到布局"开始变丑"的临界点。

流体排版 clamp()：font-size: clamp(1rem, 4vw, 3rem) 三个参数分别是最小值、理想值、最大值。4vw 让字号随视口连续变化（4% of viewport width），1rem 是下限保护（手机上不至于太小），3rem 是上限保护（4K 屏上不至于太大）。无需媒体查询，字号连续变化而非阶梯跳变——这是"内在设计"理念的体现。

视口单位进化：vh 在移动端有"地址栏收缩"问题——100vh 可能比实际可见区域高。2022 年新增 dvh（dynamic viewport height，随地址栏收缩动态调整）、svh（small viewport height，地址栏展开时的高度）、lvh（large viewport height，地址栏收起时的高度）。移动端全屏布局推荐用 100dvh 替代 100vh。

容器查询 @container（2023 年 Chrome 105 / Firefox 110 / Safari 16 全浏览器支持）：让组件根据自身容器宽度而非视口宽度响应。这是响应式设计的范式转变——从"页面响应视口"到"组件响应容器"。同一个卡片组件放在 200px 侧栏和 800px 主区时，可以自动呈现不同的布局，无需 JavaScript 判断位置。container-type: inline-size 声明容器后，用 @container (min-width: 400px) 写组件级断点。

关键代码
/* ── 移动优先：小屏默认,大屏增强 ── */
.grid {
  grid-template-columns: 1fr;       /* 手机:单列 */
}
@media (min-width: 640px) {       /* 平板 */
  .grid { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 1024px) {      /* 桌面 */
  .grid { grid-template-columns: repeat(3, 1fr); }
}

/* ── 流体排版——clamp 三参数 ── */
h1 {
  font-size: clamp(1.5rem, 4vw, 3rem);
  /* min=24px, ideal=4%视口, max=48px */
}

/* ── 移动端视口：dvh 替代 vh ── */
.fullscreen {
  height: 100dvh;  /* 动态视口高度 */
  /* 旧: 100vh (移动端地址栏收缩时会溢出) */
}

/* ── 容器查询：组件响应容器 ── */
.card-wrapper {
  container-type: inline-size;  /* 声明容器 */
}
@container (min-width: 400px) {
  .card {
    display: flex;          /* 宽: 横向布局 */
    flex-direction: row;
  }
}
@container (max-width: 399px) {
  .card {
    display: block;         /* 窄: 纵向堆叠 */
  }
}
